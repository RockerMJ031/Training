Twenty-five hours of full-fleet burn inside a seven-day window is the real constraint. It means a fleet this size cannot run continuously — it must run in bursts, and the orchestrator's main economic job is deciding which bursts are worth it.

The single largest sink

Rework, not work. Every token spent today on a wrong premise was spent twice: once producing the wrong thing, once undoing it. Two false P0 security escalations were filed and retracted. One investigation branch was designed, built into a PR, and closed unmerged. One root-cause hunt ran two levels deep before the human revealed he had already fixed the thing by hand.

Failure modes, grouped

Ten separate mistakes collapse into four recurring shapes. Naming the shape is more useful than listing the incidents.

Shape 1 · dominant

Treating a report as a verified fact

An agent reports a finding; the orchestrator forwards it as established and acts on it. Two P0 escalations, one wrong root-cause hunt, and one mis-scoped fix all trace here. The tell: the write-up says "confirmed" but no command in the transcript produced that confirmation.

Shape 2

Partial data, whole conclusion

Pagination not exhausted; output truncated by the orchestrator's own head; a 200-row page mistaken for a 5,007-row table. Same error the orchestrator had spent the day correcting in others.

Shape 3

Zeros that mean different things

A query returning nothing can mean "no data", "filtered out", "no permission", or "the call failed". Three separate incidents came from collapsing these. The fix that stuck: prove the collection is non-empty by a path that bypasses the filter, then interpret the zero.

Shape 4

Acting without closing the loop

PRs merged without telling the author. A freeze order lifted for five lanes and forgotten for four. Both cost hours of agent idle time while the orchestrator believed the fleet was busy.

The counter-pattern that worked

Agents pushed back on the orchestrator seven times and were right every time — including correcting a decision criterion that would have made a daily report cry wolf on every normal day, rejecting a bulk write of 5,001 rows because no sample existed to validate the mapping rule, and refusing to supply a precision figure the orchestrator asked for on the grounds that it would be false precision. A fleet where agents will contradict the orchestrator is worth more than a fleet that complies.

Still needed

  • Monitors that outlive the session. The current ones die when the orchestrator session ends. Making them OS-level services is the obvious next step and has not been done.
  • A "reply owed" queue. Nothing structurally prevents merging a PR and never telling its author. This should be mechanical, not a discipline.
  • Verification tier on incoming reports. Agent findings should arrive tagged measured / inferred / reported-by-another, and only measured should be forwardable as fact without re-running the command.
  • Full-output discipline. A lint that flags head/limit in any command whose result feeds a completeness claim.
  • Per-agent credentials. Would fix attribution properly and let permissions be scoped per lane instead of every agent holding the same keys.

Notes for a peer running the same structure

Written for someone with an orchestrator-and-agents setup that is burning through quota faster than expected. Ordered by how much they saved here.

1 · biggest lever

Pay for verification once, not for rework twice

The most expensive tokens are the ones that undo earlier tokens. Before an orchestrator forwards an agent's finding — especially a scary one — it should re-run the one command that proves it. A 30-second check prevented far less than it cost today, because it wasn't done: two escalations, one built-then-closed PR, one two-level root-cause hunt.

2

Never let a monitor exit on the event it monitors

Exit-on-hit means every alert costs a full orchestrator turn just to restart the watcher — and creates a blind window. A long-running process that dedupes and emits only deltas costs almost nothing and never has a gap.

3

Close the loop in the same turn you act

Agents end their turns with a question. If you merge their work and don't reply, they sit. Nine merged PRs sat unacknowledged here while their authors waited. That is pure waste — and worse, the orchestrator re-derives fleet state repeatedly because it can't tell idle from busy.

4

Use a shared ledger as memory, not the conversation

Every fact worth keeping goes into a table both sides read: what's in flight, what it's waiting on, who owes what. Re-explaining context in prose each turn is the quiet, continuous drain. It also survives context compaction, which conversation does not.

5

Make agents write to disk before they compact

Every lane here keeps a progress file. When an agent's context fills and compacts, it reloads from disk instead of reconstructing from a summary. Agents that reconstruct produce subtly wrong state — and then act on it.

6

Tier the models deliberately

Sub-agents default to the mid-tier model; the top tier is reserved for architecture judgement, long-document synthesis, and cross-module debugging. Single-field lookups and format conversions drop to the cheapest tier. Inheriting the orchestrator's model everywhere is a silent multiplier.

7

Gate at the boundary, not in review

Publishing runs through one script that chains pre-flight → publish → smoke test, with no way to skip a step. It blocked two bad publishes today. A gate that cannot be bypassed is cheaper than any amount of reviewing, because it costs nothing when everything is fine.

8

Let agents refuse

Explicitly reward pushback. The most valuable outputs today were an agent declining to produce a number it called false precision, and another refusing a 5,001-row bulk write for lack of a validation sample. Compliance is cheap to get and expensive to have.

If only one thing changes

Instrument the difference between work and rework. Count the tokens spent on things later retracted, reverted, closed unmerged, or investigated after they had already been fixed. In this session that category was large enough to be the leading line item — and it is invisible unless someone deliberately counts it.
